      DataSchemer (DS) is a lightweight, schema-driven library for parsing, validating, and typing structured user input into clean, well-defined Python data structures.

      DS is designed to sit at the boundary between user-facing interfaces (command-line tools, configuration files, simple APIs) and internal application logic. Schemas describe what data is expected and how it should be interpreted; DS handles type coercion, validation, defaults, and structural mapping in a consistent, reusable way. DS can naturally be employed within a simple script requiring user input, or a substantial software suite with a deep command line interface.

      Key ideas include:

      • Declarative schemas expressed as plain Python dictionaries, with support for reuse and extension via inheritance.
      • Strict, predictable parsing, with optional support for simple mathematical expressions (basic arithmetic), evaluated explicitly and safely.
      • First-class CLI integration, including help text, validation, and tab completion
      • Minimal assumptions, making the core a useful utility independent of CLI applications.

      DataSchemer serves as the backbone for user input in the Principia Materia software suite, but DS is a standalone utility that should be useful in other applications.

      1 - Getting Started

      DataSchemer lets you define the shape of your input once, and then rely on it to parse, validate, and structure user input consistently across your application.

      At its core, DataSchemer uses schemas to describe what input is expected and how it should be interpreted. From that description, it handles type coercion, validation, defaults, and structured results for you.

      A first example

      Suppose your program expects a set of lattice vectors and an optional scale factor. You would like to accept human-friendly input, but work internally with numeric data.

      A simple example

      from data_schemer.schema_projector import SchemaProjector

schema = {
  "variables": {
    "lattice_vectors": {
      "type": "float-matrix",
      "help": "3×3 lattice vectors",
    },
    "scale": {
      "type": "float",
      "optional": True,
      "default": 1.0,
      "help": "Scale factor applied to the lattice vectors",
    },
  }
}

input_data = {
  "lattice_vectors": """
    0 1 1
    1 0 1
    1 1 0
  """,
  "scale": "4.8",
}

result = SchemaProjector(schema, input_data)

print (result.data)
print (result.data_tuple.lattice_vectors)

      The output is

      {
  'lattice_vectors': array([[0., 1., 1.],
                            [1., 0., 1.],
                            [1., 1., 0.]]),
  'scale': 4.8
}

[[0. 1. 1.]
 [1. 0. 1.]
 [1. 1. 0.]]

      Basic substituion and arithmetic is safely supported. A hexagonal lattice may be entered as

      input_data_tri = {
  "lattice_vectors": """\
    a=2.23  c=5.8
    a*r3/2  a/2  0
    a*r3/2 -a/2  0
    0       0    c
  """,
  "scale": "1.0",
}

result = SchemaProjector(schema, input_data_tri)

print(result.data["lattice_vectors"])

      yielding

      [[ 1.93123665  1.115       0.        ]
 [ 1.93123665 -1.115       0.        ]
 [ 0.          0.          5.8       ]]

      2 - Guides

      Practical, copy-paste usage examples for DataSchemer.

      2.1 - Coercing numbers

      DataSchemer includes utilities for converting loosely structured numeric input (strings, expressions, and simple matrices) into structured Python data.

      These tools live in coerce_numbers.py.

      Import

      from data_schemer.coerce_numbers import coerce_number_list_with_substitutions

      Scalars and expressions

      coerce_number_list_with_substitutions("1/2", dtype=float)
# -> [0.5]

coerce_number_list_with_substitutions("3*4 + 1", dtype=int)
# -> [13]

      Supported syntax includes:

      • +, -, *, /
      • exponent notation (1e-3, 2E+4)
      • square roots via rN (e.g. r2)

      Separators and matrices

      Input can contain multiple values and matrices using common separators:

      • spaces

      • commas

      • semicolons

      • newlines

        coerce_number_list_with_substitutions(“1 2 3”, dtype=int)

        -> [1, 2, 3]

        coerce_number_list_with_substitutions(“1,0;0,1”, dtype=int)

        -> [[1, 0], [0, 1]]

      The result is always a nested Python list (not a NumPy array).

      Header substitutions

      You can define symbolic values at the top of a block and reuse them below.

      text = """
a=0.5 b=1/3
a, b
0.0, 2*a
"""

coerce_number_list_with_substitutions(text, dtype=float)
# -> [[0.5, 0.3333333333333333], [0.0, 1.0]]

      Fractions vs floats

      If you want exact rational arithmetic, use Fraction.

      from fractions import Fraction

coerce_number_list_with_substitutions("1/3", dtype=Fraction)
# -> [Fraction(1, 3)]

      When to use this directly

      Use numeric coercion utilities directly when:

      • parsing numeric text files
      • accepting expressions from users
      • preprocessing data before schema validation

      In schema-driven workflows, these functions are typically called indirectly by SchemaProjector.

      2.2 - SchemaProjector

      SchemaProjector is the core validation and typing engine of DataSchemer.

      It takes:

      • a schema definition
      • raw input data

      and produces validated, typed Python data. Validation happens during construction.

      Basic example

      from data_schemer.schema_projector import SchemaProjector

schema = {
  "variables": {
    "a": {"type": "int", "optional": False},
    "b": {"type": "float", "optional": False},
  }
}

raw = {"a": "1", "b": "2.5"}
p = SchemaProjector(schema, raw)

assert p.data["a"] == 1
assert p.data["b"] == 2.5

      Single vs multi-schema definitions

      Single schema (no name)

      If the schema contains a top-level variables key, it is treated as a single schema and given the default name "default".

      schema = {
  "variables": {
    "x": {"type": "int", "optional": False},
  }
}

p = SchemaProjector(schema, {"x": "3"})
assert p.schema_name == "default"

      Multiple schemas with inheritance

      schema = {
  "base": {
    "variables": {
      "a": {"type": "int", "optional": False},
    }
  },
  "derived": {
    "inherit": ["base"],
    "variables": {
      "mode": {
        "type": "string",
        "optional": False,
        "choices": ["fast", "accurate"]
      }
    }
  }
}

p = SchemaProjector(schema, {"a": "2", "mode": "fast"}, "derived")
assert p.data["a"] == 2
assert p.data["mode"] == "fast"

      Arrays and substitutions

      Array-typed variables invoke numeric coercion.

      schema = {
  "variables": {
    "m": {"type": "float-array", "optional": False},
  }
}

p = SchemaProjector(schema, {"m": "1,0;0,1"})

      Named array substitutions

      Some symbolic array tokens are predefined. For example, I denotes the identity matrix:

      p = SchemaProjector(schema, {"m": "2I"})

      This produces 2 × identity.

      Accessing results

      Common properties include:

      • data – typed output
      • raw_data – raw input after defaults are applied
      • data_tuple – namedtuple view
      • schema_variables – resolved variable definitions

      Aliasing and object construction

      A variable may define code_alias, which renames it when instantiating a target class.

      class Foo:
  def __init__(self, x):
    self.x = x

schema = {
  "variables": {
    "a": {"type": "int", "optional": False, "code_alias": "x"},
  }
}

p = SchemaProjector(schema, {"a": "5"})
obj = p.get_instance(Foo)
assert obj.x == 5

      Extending domains

      You can extend supported types and array substitutions by creating a derived projector class:

      Projector2 = SchemaProjector.domain_definitions(
  type_definitions={"double": lambda x: int(x) * 2},
  array_by_name={}
)

schema = {"variables": {"a": {"type": "double", "optional": False}}}
p = Projector2(schema, {"a": "4"})
assert p.data["a"] == 8

      2.3 - SchemaCommandLine

      SchemaCommandLine generates a command-line interface directly from a schema.

      It builds:

      • argparse options
      • schema-driven validation via SchemaProjector
      • optional object instantiation

      Basic CLI

      from data_schemer.schema_command_line import SchemaCommandLine

schema = {
  "variables": {
    "a": {"type": "int", "optional": False},
    "b": {"type": "float", "optional": False},
  }
}

cli = SchemaCommandLine(schema)
print(cli.data)

      Usage:

      python tool.py --a 2 --b 3.5

      YAML input files

      If your schema defines an input_files variable of type string-list, the CLI can merge YAML files before applying CLI overrides.

      schema = {
  "variables": {
    "input_files": {"type": "string-list", "optional": True},
    "a": {"type": "int", "optional": False},
  }
}

      Usage:

      python tool.py --input-files params.yaml more.yaml --a 3

      Required input files

      Schemas can enable a positional required file using required_file.

      schema = {
  "variables": {
    "a": {"type": "int", "optional": False},
  },
  "required_file": {
    "enabled": True,
    "apply_as_schema_data": True
  }
}

      Usage:

      python tool.py config.yaml --a 3

      Data precedence

      When multiple sources are present, precedence is:

      1. YAML input files
      2. Required file (if applied as schema data)
      3. Command-line arguments

      Later sources override earlier ones.

      Target object construction

      If a target class is provided, the CLI can instantiate it after schema validation.

      class Solver:
  def __init__(self, a, b):
    self.a = a
    self.b = b

cli = SchemaCommandLine(schema, target_class=Solver)
obj = cli.target_obj

      Error handling

      There are two layers of validation:

      • argparse handles syntax and missing positional arguments (raises SystemExit)
      • SchemaProjector enforces semantic rules (raises exceptions)

      2.4 - render data

      DataSchemer provides small utilities for formatting data as YAML-parsable text.

      These functions live in render_data.py. The goal is not full YAML serialization, but stable, readable output suitable for copy-paste into configuration files.

      Example

      from data_schemer.render_data import format_data
import numpy as np

data = {
  "positions": np.array([
    [0.5, 0.5, 0.5],
    [0.0, 0.0, 0.0],
    [0.5, 0.0, 0.0],
  ])
}

print(format_data(data))

      Produces output like:

      positions:
  [[ 0.5, 0.5, 0.5 ],
   [ 0  , 0  , 0   ],
   [ 0.5, 0  , 0   ]]

      Notes

      • Arrays are formatted for readability rather than compactness.
      • Floating-point values are trimmed and aligned.
      • Output is YAML-compatible but intentionally minimal.

      For full serialization and round-tripping, use standard YAML libraries.
