    Conventional Text and DataCanon

    Many useful files are not structured serializations such as Shorthand, YAML, or HDF5. They are ordinary text: lines, whitespace-delimited columns, comments, and sometimes several labeled sections. DataCanon Tools bridges these files and DataCanon Instances (DCIs):

    ordinary text → dc-from-text → DCI → dc transformations → dc-to-text → ordinary text

    dc-from-text gives ordinary text an explicit DCI structure. The resulting DCI can be selected, reshaped, converted, or otherwise processed by dc. dc-to-text converts supported DCI structures back to conventional text.

    Install the commands and enable completion

    The dc, dc-from-text, and dc-to-text commands are provided by DataCanon Tools. Activate the environment in which DataCanon Tools is installed before using them.

    Register completion for each command:

    eval "$(register-python-argcomplete dc)"
eval "$(register-python-argcomplete dc-from-text)"
eval "$(register-python-argcomplete dc-to-text)"

    Add those registrations to the appropriate shell initialization file after environment activation if completion should be enabled automatically.

    Begin with a list of lines

    Consider table.txt:

    # batch A
1 10
2 20
3 30

    With no transformation options, dc-from-text makes every line a String in a List:

    dc-from-text table.txt

    [ "# batch A", "1 10", "2 20", "3 30" ]

    Line terminators frame the input and are not included in the individual Strings. Internal empty lines are retained as empty Strings. A final line terminator does not create an additional empty line.

    Split lines into fields

    Drop full-line comments and split each remaining line on runs of whitespace:

    dc-from-text table.txt --comments drop --split-fields

    [
  [ "1", "10" ],
  [ "2", "20" ],
  [ "3", "30" ]
]

    The result is a List of rows, but every field is still a String. Empty and ragged rows are permitted. Use --drop-blank-lines when whitespace-only lines should be removed before further processing.

    By default, field splitting treats runs of spaces, tabs, and other whitespace as one separator. Use a literal delimiter for comma-separated or similarly delimited data:

    dc-from-text values.csv --split-fields --delimiter ,

    Literal splitting preserves empty fields. --delimiter therefore requires --split-fields.

    Parse fields as Shorthand

    Add --parse-shorthand to parse every resulting String as one strict Shorthand value:

    dc-from-text table.txt --comments drop --split-fields --parse-shorthand

    [
  [ 1, 10 ],
  [ 2, 20 ],
  [ 3, 30 ]
]

    The fields are now Integer DCIs rather than Strings. Fractions, Floats, Complex values, quoted Strings, and other complete Shorthand expressions can be used in the same way. Parsing is strict and processes each field once; unquoted words are not Shorthand Strings.

    Without --split-fields, --parse-shorthand parses each complete line. This allows a file containing one DCI expression per line to become a List of those DCIs.

    Choose the output shape

    Line splitting and field splitting are independent:

    OptionsResulting DCI
    NeitherList of line Strings
    --split-fieldsList of rows containing String fields
    --no-split-linesOne root String containing the text document
    BothOne flat List of String fields

    For example, splitting fields without retaining rows gives one flat List:

    dc-from-text table.txt --comments drop --no-split-lines --split-fields --parse-shorthand

    [ 1, 10, 2, 20, 3, 30 ]

    With neither field splitting nor Shorthand parsing, --no-split-lines preserves each data block as a String, including its final newline when one is present. Shorthand displays multiline Strings as literal blocks. The apparent blank line before the closing """ represents a preserved terminal newline; it is not an additional input line.

    The line boundaries can still guide comment classification and blank-line removal. --no-split-lines controls the resulting DCI shape; it does not disable line-aware preprocessing.

    Keep, drop, collect, or section comments

    A comment line is one whose first non-whitespace character is #. --comments accepts four modes:

    ModeBehavior
    keepKeep comments as ordinary data lines. This is the default.
    dropRemove comment lines before constructing the data.
    collectReturn one Mapping with comments and data fields.
    sectionsStart a new section when comments follow data.

    For example, sections.txt might contain:

    # first batch
1 10
2 20
# second batch
1 15
2 30

    Preserve the two sections and parse their tabular data:

    dc-from-text sections.txt --comments sections --split-fields --parse-shorthand

    [
  {
    "comments": [ "# first batch" ],
    "data":
      [
        [ 1, 10 ],
        [ 2, 20 ]
      ]
  },
  {
    "comments": [ "# second batch" ],
    "data":
      [
        [ 1, 15 ],
        [ 2, 30 ]
      ]
  }
]

    Use --no-split-lines when each section’s data should instead remain one text block:

    dc-from-text sections.txt --comments sections --no-split-lines

    The result retains the same section Mappings, with each data value represented by a multiline String. Combining --no-split-lines, --split-fields, and --parse-shorthand instead gives each section one flat List of typed fields.

    collect groups all comments together and all data together. It therefore does not preserve the original interspersed positions of comments. Use sections when those boundaries matter.

    Transform conventional data with dc

    Because dc-from-text prints Shorthand, its result can feed the ordinary dc pipeline. Convert the numerical table to an Array and transpose it:

    dc-from-text table.txt --comments drop --split-fields --parse-shorthand \
  | dc - --to-array --transpose

    array(
  [[1, 2, 3],
   [10, 20, 30]]
)

    Any compatible dc selection, conversion, or array operation can be composed in the same way. The text adapter only constructs the initial DCI; subsequent operations use the normal DataCanon pipeline.

    Convert a DCI back to text

    dc-to-text assigns meaning according to the DCI’s structure:

    DCI structureText interpretation
    Root StringComplete text document, emitted verbatim
    List of scalarsOne item per line
    List of Lists or TuplesDelimited rows
    TupleOne delimited row
    Rank-one ArrayOne element per line
    Rank-two ArrayDelimited rows
    Recognized comment MappingComment lines followed by its data

    For example:

    echo '[["red", 3], ["blue", 5]]' | dc-to-text -

    red 3
blue 5

    Choose another field delimiter when needed:

    echo '[["red", 3], ["blue", 5]]' | dc-to-text - --delimiter ,

    red,3
blue,5

    A root String is different from a List containing one String:

    "hello"       → hello       (no newline is invented)
["hello"]     → hello\n     (one newline-terminated line)

    This distinction preserves empty documents, empty lines, and the presence or absence of a final newline.

    Strings used as individual lines or fields may not themselves contain line breaks. Arrays of rank greater than two and arbitrary Mappings do not have an unambiguous conventional-text representation and are rejected. The exact comments/data Mappings produced by dc-from-text are recognized.

    Round-trip a text document

    A root String provides a direct text-document round trip:

    dc-from-text notes.txt --no-split-lines \
  | dc-to-text - > restored.txt

diff -u notes.txt restored.txt

    No output from diff means that the text agrees. The commands operate on Unicode text, not arbitrary binary bytes. Field splitting, comment removal, Shorthand parsing, and DCI transformations deliberately change the document or its structure and should not be expected to reproduce its original spacing.

    Use the conversion functions from Python

    The same adapters are public Python functions:

    from data_canon import as_dc_instance
from data_canon_tools import dci_to_text, text_to_dci

source = "1 10\n2 20\n"

table = text_to_dci(
    source,
    split_fields=True,
    shorthand=True,
)

assert table == as_dc_instance([[1, 10], [2, 20]])
assert dci_to_text(table) == source

document = text_to_dci(source, split_lines=False)
assert document == as_dc_instance(source)
assert dci_to_text(document) == source

    text_to_dci() accepts the same conceptual controls as dc-from-text: split_lines, split_fields, delimiter, shorthand, comments, and drop_blank_lines. dci_to_text() accepts a field delimiter and applies the structural interpretation described above.
