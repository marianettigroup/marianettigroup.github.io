    Shorthand Preprocessing

    Overview

    Shorthand preprocessing provides three conveniences for entering scientific data by hand: compact List notation, named textual substitutions, and scalar mathematical evaluation with eval(...).

    Preprocessing transforms text into strict Shorthand. Parsing that text then constructs a DataCanon Instance. This guide introduces each feature separately before showing how they work together.

    Start with one compact List

    Ordinary Shorthand Lists use brackets and commas:

    [1, 2, 3]

    Compact notation lets you enter the same List using angle brackets and spaces:

    <1 2 3>

    Use preprocess_shorthand() to expand it:

    from data_canon import preprocess_shorthand

source = "<1 2 3>"
prepared = preprocess_shorthand(source)
print(prepared)

    The resulting text is:

    [1, 2, 3]

    No DataCanon Instance has been constructed yet. prepared is a Python String. Parse that String to construct the List DCI:

    from data_canon import parse_shorthand

instance = parse_shorthand(prepared)

    These are separate steps: preprocessing expands input notation; strict parsing interprets the resulting Shorthand and validates the data.

    A compact group always produces a List, even when it contains only one item:

    <6>  -> [6]

    Empty compact groups are invalid. Use ordinary [] for an empty List.

    Enter nested Lists

    A comma can separate rows whose items are separated by spaces:

    <1 2 3, 4 5 6>

    expands to:

    [
  [1, 2, 3],
  [4, 5, 6]
]

    A semicolon can introduce another level:

    <1 2, 3 4; 5 6, 7 8>

    expands to:

    [
  [
    [1, 2],
    [3, 4]
  ],
  [
    [5, 6],
    [7, 8]
  ]
]

    At each level, the preprocessor looks for separators in this order:

    1. Newline.
    2. Semicolon.
    3. Comma.
    4. Horizontal whitespace: space, tab, or carriage return.

    The first separator that splits the contents into multiple nonempty parts establishes the outer level. Each part is then processed in the same way. Newlines therefore introduce a level outside semicolons, commas, and spaces. Explicitly nested angle-bracket groups are also supported.

    The layouts above illustrate the resulting structure; exact output spacing is not important to strict parsing. Avoid repeated or trailing separators while their treatment remains a Version 1 draft finalization item.

    Existing structures remain intact

    Separators inside quoted Strings or balanced (), [], and {} do not split items. For example:

    <[1,2] 3>

    becomes:

    [[1,2], 3]

    The inner [1,2] is one item. Likewise,

    <"Sr Ti O" 3>

    becomes:

    ["Sr Ti O", 3]

    The spaces inside the String do not introduce List items.

    Construct an Array when needed

    Compact notation alone creates Lists. To enter an Array, place it inside an Array expression:

    source = 'array(<1.0 0.0, 0.0 1.0>, dtype="float64")'
prepared = preprocess_shorthand(source)
instance = parse_shorthand(prepared)

    The prepared text represents:

    array([[1.0, 0.0], [0.0, 1.0]], dtype="float64")

    The strict Array parser constructs the Array. Compact notation supplies its numerical body without itself performing Array inference.

    Substitute one name

    A substitution associates a name with replacement text. Define the name before |, then use it in the document body:

    species="Sr" | {"species": species}

    Preprocessing produces:

    {"species": "Sr"}

    In Python:

    source = 'species="Sr" | {"species": species}'
prepared = preprocess_shorthand(source)
instance = parse_shorthand(prepared)

    The name species is an input convenience. After substitution, the parser receives an ordinary Shorthand Mapping.

    Multiple Substitutions

    Separate definitions with whitespace. Whitespace around = is permitted:

    species = "Sr"
position = [0.5, 0.5, 0.5] |
{
  "species": species,
  "position": position
}

    becomes:

    {
  "species": "Sr",
  "position": [0.5, 0.5, 0.5]
}

    Definitions can contain Strings, Tuples, Arrays, Mappings, or other text:

    label = "oxygen"
site = (1/2, 1/2, 0)
lattice = array([[1.0, 0.0], [0.0, 1.0]], dtype="float64") |
{
  "label": label,
  "site": site,
  "lattice": lattice
}

    Replacement text is inserted literally. It is not separately parsed as a DCI; only the final document must be valid strict Shorthand. Replacement text can therefore also be an expression fragment used later inside eval(...).

    Name rules and protected Strings

    A name begins with an ASCII letter or underscore, followed by ASCII letters, digits, or underscores. Names are case-sensitive and must be unique.

    Substitution replaces complete identifier-like tokens. A definition for a does not replace part of alpha or a2, and nothing is substituted inside quoted Strings:

    a=3 | {"value": a, "text": "a"}

    becomes:

    {"value": 3, "text": "a"}

    Inline substitutions are applied in one pass. They do not recursively resolve references between inline definitions. Define each replacement directly rather than relying on one inline name to expand another.

    Supply substitutions from Python

    Instead of placing definitions in the input, supply a mapping of names to replacement Strings:

    prepared = preprocess_shorthand(
    '{"species": species, "position": position}',
    substitutions={
        "species": '"Sr"',
        "position": "[0.5, 0.5, 0.5]",
    },
)
instance = parse_shorthand(prepared)

    The result is the same Mapping as in the inline example. The values in substitutions must be text. The quotation marks in '"Sr"' are intentional: they make the replacement a Shorthand String literal.

    External substitutions may also be used in inline definitions:

    prepared = preprocess_shorthand(
    'site=(x, x, 0) | {"position": site}',
    substitutions={"x": "1/2"},
)

    This produces:

    {"position": (1/2, 1/2, 0)}

    External names are substituted once in each inline definition and once in the body. Inline names are then substituted once in the resulting body. An inline name must not conflict with an externally supplied name.

    Evaluate one scalar expression

    Use eval(...) when you want to compute a numerical result before parsing:

    prepared = preprocess_shorthand("eval(2 + 3)")
print(prepared)

    Output:

    5

    Parsing prepared constructs Integer 5:

    instance = parse_shorthand(prepared)

    Evaluation is explicit. The preprocessor does not perform arithmetic on expressions outside eval(...).

    Supported arithmetic

    The evaluator supports real integer and floating-point literals, parentheses, unary + and -, binary +, -, *, /, and **, and real sqrt(...):

    InputResulting Shorthand
    eval(1/2)0.5
    eval((2 + 3)*4)20
    eval(2**10)1024
    eval(sqrt(9) + 1)4
    eval(-2**2)-4
    eval(5+(1.89-2.53)*6/3.72)3.967741935483871

    Operator precedence follows Python. Division / performs true division; exponentiation uses **, not ^.

    Intermediate values use arbitrary-precision integers and binary64 floating-point arithmetic. If a final Float has an exactly integral value, it is emitted as an Integer. Otherwise, a finite floating-point result is emitted as a Float literal. No tolerance is used to decide whether a value is integral.

    Evaluation versus stored structure

    Strict Shorthand can store an irrational value as a structured Coefficient:

    1/2 * sqrt(3)

    That expression remains a Coefficient when preprocessed. To compute a floating-point approximation instead, request evaluation:

    eval(1/2 * sqrt(3))

    This distinction lets you choose between preserving scientific structure and performing numerical arithmetic before constructing the DCI.

    Evaluation limits

    The evaluator supports real scalar arithmetic only. It excludes unresolved names, arbitrary function calls, Arrays, indexing, attribute access, and general code execution.

    Division by zero, negative real square roots, complex results, and nonfinite floating-point results are rejected. Implementations may limit expression length, nesting, and intermediate integer size. Cross-language numerical conformance details remain recorded in the Version 1 draft specification.

    Combine the features

    Once each feature is familiar, they can be used together. Consider entering a symmetric matrix with repeated numerical parameters:

    a=1.1 b=0.2 |
<a 0 b, 0 a 0, b 0 eval(-a)>

    First, compact List notation expands:

    [
  [a, 0, b],
  [0, a, 0],
  [b, 0, eval(-a)]
]

    Next, substitutions are inserted:

    [
  [1.1, 0, 0.2],
  [0, 1.1, 0],
  [0.2, 0, eval(-1.1)]
]

    Finally, eval(...) is evaluated:

    [
  [1.1, 0, 0.2],
  [0, 1.1, 0],
  [0.2, 0, -1.1]
]

    Strict parsing now constructs a List of Lists. To construct an Array, wrap the compact body in array(..., dtype="float64").

    The order also matters when replacement text contains spaces. For example:

    coefficient=1/2 * sqrt(3) | <coefficient 0>

    Compact List expansion happens first:

    [coefficient, 0]

    Substitution then produces:

    [1/2 * sqrt(3), 0]

    The spaces within the replacement Coefficient do not split it into additional List items because compact List expansion has already finished.

    Use preprocessing explicitly

    Call parse_shorthand() directly for strict Shorthand. When preprocessing is wanted, call preprocess_shorthand() first and parse its result.

    Quoted Strings are protected during every stage. Text such as "<1 2>", "eval(2 + 3)", or "a | b" remains ordinary String content.

    Preprocessing does not change DataCanon’s types or identity rules. YAML DC> values and .dcs persistence files use strict Shorthand and do not implicitly perform preprocessing.

    For the detailed rules, see the Shorthand Preprocessing specification.
